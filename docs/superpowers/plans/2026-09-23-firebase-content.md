## 新增：私有笔记同步（已确认并实施）

以下原始讨论已由用户确认的设备匿名方案取代：使用 Keychain UUID + Firebase Anonymous Auth；路径为 users/{uid}/devices/{deviceUUID}/accounts/{accountHash}/notes/{noteID}。Firebase UID 是访问控制边界，账号散列仅作本机业务账本隔离，不保证重装或换机恢复。照片保留本地。具体实施及验证见 `2026-09-23-private-notes.md`。

### 原始方案讨论（历史记录，非当前执行要求）

- 建议路径：users/{firebaseUID}/notes/{entryID}。必须由 Firebase Authentication 验证用户身份，不能信任客户端自行传入的业务 userID。
- 保留现有业务登录的推荐方案：业务服务端验证现有登录凭据，再签发绑定该用户的 Firebase Custom Token。私钥不得进入 App；现有接口尚未发现 Custom Token 支持，工作区没有对应业务服务端实现。
- 替代方案：增加独立 Firebase 登录与明确的账号关联流程。匿名认证不能被当作跨设备恢复同一业务账号的完整方案，也不能自动混合不同业务用户的笔记。
- 每个用户只可读取、新建、修改和删除自己的笔记；校验允许字段、类型、长度和不可变创建时间。草稿同样为私有数据。规则部署前需要覆盖跨用户读写与未登录访问拒绝测试。
- 保留本地存储，按账号记录待同步变更，上传成功后确认状态。先约定冲突解决和删除标记，避免离线删除后云端旧笔记复活；退出或切换账号必须停止旧账号同步任务。
- 现有删除账号为本地处理；云端笔记上线时必须同步实现云端数据删除，失败不可伪装成成功。
- 笔记的 photos 当前为本地引用，不可直接当作跨设备可读地址。不得上传到公开 Hosting。维持不绑定账单时，照片先保留本地；如需私有照片跨设备同步，另行确认 Cloud Storage 账单或其他私有存储方案。
- 此次只补充需求与阻塞点，不开放私有读写规则，不创建匿名账号，不上传用户笔记。

## 架构

- 项目 coast-wild-20260915，数据库 (default)，区域 us-east1。
- 免费额度优先，不关联账单。采用 Firestore Standard 配合 Firebase Hosting 的公开静态图片 CDN；不启用 Cloud Storage、Functions 或其他需要付费的服务。
- 初始 Firestore 规则全部拒绝，数据库初始化不等于数据迁移完成。
- 公共课程内容按版本发布；数据库保存结构化内容，Hosting 保存发布用配图。App 内置内容作为首次离线兜底，成功下载并验证的内容才可替换缓存。
- 管理员发布内容；客户端不允许写课程。不得将任何私有文件混入 Hosting 发布目录。
- App 注册使用真实 Bundle ID com.huankecontact.test，而非测试业务接口的 pkg。
