# 第一版原生能力拆分方案

## 已确认范围

- 第一版分支：`codex/native-uikit`。
- 第二版分支：`codex/native-coin-learning`，保留业务 Web、JS Bridge、ATT/Adjust、本地预置内容与已有内购能力。
- 第一版实际移除上述四类能力，不只是用运行时开关隐藏。
- “本地 JSON”仅指内置 `catalog.json` 等预置业务内容及首次启动/失败兜底；不包括网络 JSON 编解码、云端内容缓存、手记本地保存与同步队列、资源目录 Contents.json。
- 保留隐私协议、课程正文展示容器，移除其中若有的特权业务 JS 通道，不删除正常正文展示。

## 当前依据

- 第一版 HEAD 为 `131ea8b`，第二版 HEAD 为 `369385d`。
- 第二版已存在 BusinessWebController、InternalWebController、Bridge、归因代码与 catalog.json，但这不代表与第一版工作区最新实现完全一致。
- 第一版工作区有大量未提交的 Firebase、手记、内容加载与工程配置修改，另有已暂存资源修改；不得重置、覆盖、全量暂存或将未提交修改当作无关临时文件删除。
- AppDelegate 当前在远程登录成功后创建业务 Web 并启动归因；公共内容无缓存时强制加载内置 catalog.json。
- Adjust 由 CocoaPods 集成，ATT 用途声明在 project.yml 与 Xcode 工程配置中。

## 方案选择

采用按分支拆分代码与依赖。运行时开关会让第一版仍携带功能，不满足需求；另建共享模块会扩大本次改造范围，暂不采用。

## 第一版行为

1. 隐私同意、已有原生登录/会话恢复继续工作；登录成功统一进入原生主页。
2. 移除业务 Web 路由、二级业务 Web、bootstrap、业务消息注册/分发/回调与相关专用测试入口。共享网络、安全日志及协议正文容器按调用关系保留。
3. 审计 getStrategy 及策略状态依赖，移除仅服务 Web 切换的请求和状态；保留认证及有效协议配置，不因删 Web 而顺带更换登录协议。
4. 移除 ATT 请求、Adjust 适配器、归因协调/上报、SDK 依赖、用途声明与不再适用的配置/隐私说明；不留下伪造 Adjust 版本的请求声明。共享接口字段按真实能力处理，未知服务端兼容性单列验证。
5. 公共内容仅来自已校验云端缓存或远程获取。首次无缓存显示加载；失败显示明确错误与可重试操作，不崩溃、不加载预置内容、不永久转圈。有效空内容与加载失败区分。
6. 保留手记、图片、同步队列与缓存。删除 catalog.json 不删除资源目录元数据，不删除云端已发布的数据，不自动重新部署 Firebase。

## 第二版保护

在第一版删除前记录相关文件清单、分支基线与最新工作区差异，并保存可核对的恢复材料。对比第二版的现有实现，有选择地补齐相关能力，不把第一版已有的内购删除反向覆盖到第二版。

第二版改动必须在独立检出环境完成，不能在当前脏工作区直接切分支。若需创建 worktree，先取得用户对隔离工作区的同意。不自动提交、推送、合并或发布。

未来合并不能只依赖普通 Git merge：第一版的删除可能覆盖第二版未修改的祖先文件。维护移除清单与选择性恢复步骤，未来授权合并时分别断言原生、Web、Bridge、归因、预置内容、内购和金币消费能力；无冲突不等于功能保留。

## 验收

- 先增加第一版边界检查并确认其在改造前失败，再执行移除。
- 检查 App 源码、资源、Podfile/锁文件、生成工程与最终构建，确认第一版不包含业务 Web/Bridge、ATT/Adjust 和预置内容加载。
- 单测覆盖无缓存、有效缓存、坏缓存、云端成功/失败、重试、会话恢复及手记同步。
- 模拟器验证首次启动、登录进入原生、内容加载/失败重试、课程正文、隐私协议及手记保存。
- 第二版分别检查能力文件/依赖完整性、构建和适用回归测试；真实 H5、ATT 真机状态、Adjust 后台接收、真实支付另列未测项，不能以编译通过代替。
- 完成后列出两版修改、保留项、实际验证与未验证项；不对未来自动合并作无条件保证。

## 操作边界

本文件记录用户已确认的功能范围。实施前请用户审阅此拆分方案与第二版独立工作区安排。未获得提交/合并/推送授权，不执行此类操作。
